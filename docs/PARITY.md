# Parity register — Halation vs Higgsfield

**Measured 2026-08-04** against the repo as it stands and against `~/higgsfield-research/`
(19 reports, the 419-row live motion catalog, the 24,835-string i18n bundle, the 98-app
sitemap) plus the approved plan at `~/.claude/plans/floofy-popping-phoenix.md`.

Every count below was re-derived from the code or the corpus on the date above. Where a
number is an estimate it says so.

## 0. Where the build actually is

| | Built | Measured |
|---|---|---|

| Tests | 409 green | 295 Rust + 114 UI |

Milestone reality against the plan:

- **M0 Foundations** — complete bar two items (§3.1, §3.2).
- **M1 Core generator** — code complete, **exit criteria never run** (§3.3).
- **M2 Presets/characters** — the *engine* is built; the *content* is ~6% authored (§1).
- **M3 Audio/lipsync/compositor** — compositor built and untested in anger; audio and
  lipsync are at zero (§2).

The honest one-line summary: **Halation is a working single-surface generator. Higgsfield
is forty surfaces.** The remaining work is overwhelmingly content authoring and surface
building, not core engineering — the hard plumbing (routing, cost, jobs, keychain,
compositor) is done.

## 1. Content — the largest gap by far

This is the single biggest line item in the whole project and it is not an engineering
problem. Higgsfield's moat *is* this content.

| Asset class | Higgsfield | Halation | Gap |
|---|---|---|---|
| Motion/VFX presets | **419** (live, re-verified) | 25 | **394** |
| One-click Apps | **98** (from `/apps/sitemap.xml`) | 0 | **98** |
| Image style presets | ~100 | 0 | ~100 |
| Rendered preview clips | 1 per preset | 0 (CSS transforms only) | ~600 |

**What we already hold, for free.** Of the 419 motions, **229** are their in-house
`higgsfield` family and their public endpoint leaks the full sampler config
(`{steps:20, frames:81, strength:1.0, guide_scale:6.0}`). So for 55% of the catalog we have
their exact numeric configuration — we only need to author prompt bodies. The other **190**
(minimax 77 · kling 56 · seedance 25 · wan2\_2 17 · wan2\_5 15) expand server-side and are
UUID-only; those bodies must be written from scratch and will not match theirs.

**What is wired vs authored.** `preset.rs` (846 lines) has the whole family→variant
resolver, mix-composition cap, chain-preset validation, and the `Requires` schema. But
`list_presets()` in `commands.rs:184` returns **only** `camera::TEMPLATES` — the authored
catalog behind the engine does not exist yet. The engine is a working car with no fuel.

**Previews.** `CameraPreview.tsx` renders the *geometry* of a camera move as a CSS
transform, which is honest and free for the 25 camera presets. It says nothing useful about
a VFX preset, where the content is the point. Those need real rendered clips generated by
us — roughly 400 generations at real provider cost, repeated whenever a preset is retuned.
Budget this explicitly; it is a recurring cost, not a one-off.

**Camera controls specifically.** The plan calls for 65 (16 re-authored templates + 8
mechanical inverses + the remainder). We ship 25 — the 16 and 8 plus one. **40 short.**

## 3. Engine and plumbing gaps

### 3.1 Prices are hardcoded — a direct plan violation

The plan says: *"Prices are fetched at runtime, never hardcoded."* Every USD figure is
currently transcribed by hand into `registry.rs`. There is no `prices.json`, no launch
fetch, no daily refresh, no bundled snapshot, no fetch-timestamp in the UI.

This matters more than it sounds: the numbers go straight onto the Generate button, and
provider prices move. **Ship the fetcher before anyone relies on a displayed cost.** Note
the known trap — fal's site sits behind a bot checkpoint that 429s plain curl, so the
fetcher needs a browser-shaped request and a CI test that proves it still works.

### 3.2 `tauri-specta` not wired

TypeScript types are hand-mirrored from Rust structs. This is the exact maintenance hazard
the plan called out in WhimprFlow and explicitly said not to copy. Every command signature
change is currently a silent break waiting to happen.

### 3.3 M1's exit criteria have never been run

The code is there; the proof is not. Nothing has been verified end to end because no
provider key has ever been entered. Outstanding:

- No live generation has ever completed. Not one.
- No verification that displayed pre-flight USD matches an actual provider charge.
- **Never run on Windows.** CI bundles `x86_64-pc-windows-msvc`, but no human has launched it.
- Quit-mid-generation → reattach-on-relaunch: implemented, never exercised against a real job.
- 429 backoff: unit-tested, never seen live.
- Pixel-parity comparison against live Higgsfield at 1920×1227: not run, in either
  WKWebView or WebView2.

**This is the highest-value next action and it needs one fal key.**

### 3.3a Input media — **closed 2026-08-04**

Previously the largest functional hole: `SubmitInput` carried no media and
`submit_to_provider` sent only prompt + flags, so image-to-video, start/end
frame and reference-to-video could not work at all. Now built:

- `crates/halation-core/src/media.rs` — roles (`start`/`end`/`reference`/…) bound
  to the wire flags the vendored `MODELS.md` actually declares, with per-role
  fallback (`start_image` → `image`) and a deliberate refusal to fall back for
  `end`, since binding an end frame to `image` produces a generation that
  ignores it while looking like it worked.
- `Uploader` trait + implementations for fal
  (`POST /storage/upload/initiate` → signed `PUT`, verified against both official
  clients) and Higgsfield (`POST /files/generate-upload-url`). fal is the
  universal fallback, so one fal key makes media work on every provider.
- UI picks files through the **Tauri dialog**, which is the only thing that
  yields a real filesystem path — `<input type="file">` hides it and
  `createObjectURL` gives a `blob:` URL that resolves in the webview and nowhere
  else. Plain-browser dev falls back to data URIs.

Still unexercised against a live provider (see §3.3). Not implemented: fal's
multipart upload above 90 MB, which is refused with a clear message rather than
attempted and failed mid-transfer.

### 3.4 `from_provider` does not exist

The plan says build it day one because it powers Rerun, Recreate, "reuse settings", and
recipe import/export. Only `to_provider` is implemented. Everything downstream of it is
blocked.

### 3.5 Compositor built, unreachable

`compositor.rs` (1,695 lines) and `ffmpeg.rs` (864) are done and tested against real
ffmpeg. **No UI surface calls them.** There is no timeline, no multi-clip editor, no export
dialog. The M3 exit criterion — a 10-minute 1080p narrated export with burned-in captions —
cannot currently be attempted from the app.

### 3.6 FFmpeg binaries: one of three

Present: `ffmpeg-aarch64-apple-darwin` (51.8 MB). Missing: `x86_64-pc-windows-msvc.exe` and
`x86_64-apple-darwin`. The sidecar is correctly declared in `tauri.conf.json` and granted in
`capabilities/default.json` with an args validator.

⚖️ **And the one we have is not shippable** — see §5.

### 3.7 Auto-updater not wired

No signing key, no release feed, no update flow. M4 item.

## 4. Model roster

**68 models / 103 routes / 16 launch** against Higgsfield's live picker. Their video registry
(§3.2 of the inventory) and image registry (§4.1) are both fully transcribed into the
corpus, and `DISPLAY_OVERRIDES` fixes the four labels where their internal ID and their
sold name disagree — including the genuinely confusing pair where their `nano_banana_2` is
sold as "Nano Banana **Pro**" and their `nano_banana_flash` is sold as "Nano Banana **2**".

Roster gaps that remain:

- **Audio models are registered but unroutable** — 5 parsed from `MODELS.md`, no adapters.
- **GPT Image 2 is unpriced.** It bills on output tokens and `Billable` cannot express that.
  Currently `CostModel::Unknown`, which the resolver correctly sorts last and the UI must
  render as "price unavailable" — never as free.
- **Several fal `pricingInfoOverride` fields are blank upstream** (Kling o1, Kontext, all
  Wan image). Same handling; the Vercel feed is the fallback once §3.1 ships.
- **Route slugs marked `unverified slug`** in `registry.rs` where the corpus never captured
  the endpoint. These will fail on first real call and are the most likely source of §3.3
  surprises.

## 5. Release blockers

| Blocker | State |
|---|---|
| ⚖️ **FFmpeg licensing** | The macOS binary is from osxexperts.net, which labels its downloads *"for educational purposes only"* — incompatible with redistribution. **Must** be resolved by building FFmpeg ourselves or sourcing from a vendor with clear redistribution terms. Recorded in `NOTICE`. Blocks any public release. |
| **macOS notarization** | `build-macos.sh` and `verify-macos.sh` are ported and proven (the verifier correctly *fails* a development-certificate build). Needs a fresh Apple app-specific password — none stored on this machine. |
| **Windows installer + Store** | Nothing built. Tauri emits no MSIX; needs Microsoft's `winapp` CLI. Store registration is free as of 2026 but the identity check takes time — **start it early, it is the only clean first-install path.** |
| **Trademark clearance** | USPTO TESS + EUIPO on "Halation", classes 9/42. Not run. |
| **Domains** | `halationhq.ai` not registered; `halation.ai` Dropzone application not filed. |
| **Attorney review** | Plan recommends before M2 ends. Not engaged. Covers trade dress, copy provenance (especially camera templates), BYO-key framing, and exposing Higgsfield's own API as a provider. |

## 6. Where 1:1 is permanently impossible

State these in the README rather than letting users discover them.

1. **Soul's aesthetic.** Undisclosed base checkpoint + ~95 hand-tuned style LoRAs +
   proprietary enhancer. Substitute FLUX.2 (with FLUX.1-dev + realism LoRAs as "Photoreal")
   reaches an estimated **85–90%** of perceived quality, with a slightly artificial sheen on
   skin against Soul's amateur-phone-camera grit. Porting their preset prompts closes the
   cheapest 60% of the remaining gap. An optional literal-Soul route via the user's own
   Higgsfield key exists as an escape hatch.
2. **The 190 third-party preset bodies.** Server-side only, no leak anywhere. Names,
   thumbnails, categories and UI will be identical; rendered VFX output will differ in
   specifics. Camera presets will be very close — we have their own 5-slot templates.
3. **Veo with recognizable people.** `personGeneration: allow_all` is allowlist-gated *per
   Google Cloud project* and the allowlist attaches to the end user's project. We cannot
   grant it. Likeness-driven presets are Higgsfield's entire pitch, so this is the biggest
   UX landmine in the project. **Build the graceful-degradation path first, not last:** a
   `likeness_blocked_by_provider` error class, one-click reroute to Kling/Seedance/Wan, and
   a per-model policy badge.
4. **Their price on flagship models.** They subsidize rather than mark up. Real credit rate
   is **$0.030/credit (Ultra, $270/mo) to $0.075/credit (Starter, $15/mo)**, median
   $0.0417 — so the comparison flips by tier. Seedance 2.0 8s/720p at 36 credits costs a
   Starter subscriber $2.70 and an Ultra subscriber $1.08, against fal's $2.43.
   **Higgsfield beats BYO-key only on their most expensive plans.** We win outright on Veo
   Fast/Lite, Grok (2.4× direct from xAI), Gemini Omni, Seedream (3.7×), Recraft (10× at
   2K), Topaz upscale (2–5×), and every self-hosted path — and you never pay for a month you
   didn't use. Publish the full table including the rows where they win; that is the
   credibility.

## 7. Suggested order

1. **One fal key → run M1's exit criteria.** Everything else is speculation until a real
   generation completes. Highest value, lowest effort, and it will surface the
   `unverified slug` routes.
2. **Runtime price fetcher** (§3.1) — correctness issue, cheap.
3. **`from_provider`** (§3.4) — unblocks Rerun and recipes.
4. **Library UI** — the app currently generates media the user cannot browse.
5. **Preset content at scale** — the 229 with leaked sampler params first, since they are
   the highest-fidelity and the cheapest to author.
6. **Audio + Lipsync** — the largest *fully achievable* parity win: 7 third-party APIs and
   2 open-weight models mean genuine 1:1 is possible here, unlike Soul.
7. **Compositor UI** — makes 2,559 already-written lines reachable.
8. **Studios** — Film Studio first, as the others reuse its shell.
9. **FFmpeg licensing + notarization + Store** — before any public release.
